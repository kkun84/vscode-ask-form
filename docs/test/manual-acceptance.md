# 手動受け入れ手順

LLM APIのスタブを使う自動受け入れテストに加えて、実際のCopilotの言語モデルでの振る舞いを人が確かめる手順です。リリースの前に、GitHub Copilotにサインインした状態で行います。MAT-WEB-001は、GitHub Codespacesのようにサーバーにつないだweb版で行います。ほかはデスクトップ版で行います。CodexのハーネスとAgentsウィンドウは、サーバーにつないだweb版には無いので、デスクトップ版だけで確かめます。各手順の「検証」に、確かめる要求を書きます。

## 準備

1. リリースする`.vsix`をインストールし、VS Codeを再起動する。
2. チャットをエージェントのモードにし、ツールの一覧で「Ask Form」が有効になっていることを確かめる。

## 手順

### MAT-ASK-001 フォームで質問される

検証: REQ-ASK-001, REQ-ASK-002, REQ-ASK-003

1. チャットに「来月の社内勉強会の参加費を決めたい。会場費は14万円。参加者数と参加費を変えながら収支を見たいので、フォームで聞いて」と送る。
2. チャットの横のパネルにフォームが表示され、推奨の選択肢に「推奨」の印と理由が付き、選択肢ごとに説明が表示されることを確かめる。
3. 参加費を変えると、収支がすぐに変わることを確かめる。
4. 新しいチャットで「TODOアプリに締め切りの機能を付けるか決めたい。どちらがよいか判断する材料はまだないので、推奨なしでフォームで聞いて」と送る。質問が何も選ばれていない状態で表示され、見出しに「未回答」と出ること、そのまま「送信」を押すと送信されずにその質問が示されることを確かめる。

### MAT-ASK-002 選んだ選択肢に応じて続きを聞かれる

検証: REQ-ASK-004

1. チャットに「TODOアプリの保存先を決めたい。ブラウザならlocalStorageかIndexedDBか、サーバーならポート番号とログインの要否も決めたいので、フォームで聞いて」と送る。
2. 保存先の選択肢の下に、選んだ保存先に関係する項目だけが表示されることを確かめる。
3. 保存先を「サーバー」に変えてポート番号を直して回答し、Copilotがブラウザの保存方式に触れず、サーバーの値で続きを書くことを確かめる。

### MAT-ASK-003 順位を聞かれる

検証: REQ-ASK-005

1. チャットに「TODOアプリに足す機能を、締め切り、タグ、検索、共有の4つから決めたい。どれから作るか、優先順位をフォームで聞いて」と送る。
2. フォームに4つの機能が並び、推奨の順があれば「推奨」と理由が表示されることを確かめる。
3. 候補の「共有」を押して順位に入れ、ドラッグで一番上に動かす。順位の「検索」の「×」を押して候補に戻す。順位の行にTabで移り、Spaceで持ち上げ、↓で動かしてSpaceで置く。
4. 「送信」を押し、Copilotが並べた順で作業を進めることを確かめる。
### MAT-ASK-006 数値の範囲を聞かれる

検証: REQ-ASK-008

1. チャットに「このライブラリが対応するNode.jsの版の範囲を決めたい。下限と上限をフォームで聞いて」と送る。
2. フォームに、つまみ2つのスライダーと、下限と上限の数値の欄が表示されることを確かめる。推奨の範囲があれば「推奨」と理由が表示されることを確かめる。
3. 下限のつまみを上限より右へ動かそうとしても、上限を超えないことを確かめる。上限の欄に下限より小さい値を入れて確定すると、下限と同じ値になることを確かめる。
4. 「送信」を押し、Copilotが答えた範囲で作業を進めることを確かめる。
### MAT-ASK-005 自由な値を複数書く

検証: REQ-ASK-007

1. チャットに「このリポジトリでLintの対象から外すパスを決めたい。候補を勧めてくれていいので、フォームで聞いて」と送る。
2. フォームに、勧められたパスが並んで表示されることを確かめる。
3. 欄に「coverage」と書いてEnterを押し、足されることを確かめる。勧められたパスの1つを×で消す。
4. 「送信」を押し、Copilotが足したパスを含め、消したパスを含めずに設定を書くことを確かめる。
### MAT-ASK-007 日付と時刻を聞かれる

検証: REQ-ASK-009

1. チャットに「次のリリースの日付と、デプロイを始める時刻を決めたい。日付は来週から3か月以内、時刻は平日の9時から18時の30分刻みで、フォームで聞いて」と送る。
2. 日付の欄のカレンダーのボタンを押し、範囲外の日が選べないことと、矢印キーとEnterで日を選べることを確かめる。
3. 時刻の欄で時と分をキーボードで入れ、30分刻みに丸められることを確かめる。
4. 「送信」を押し、Copilotが選んだ日付と時刻で続きを進めることを確かめる。
### MAT-ASK-008 階層のある候補から選ばされる

検証: REQ-ASK-010

1. チャットに「このリポジトリのsrcの下で、リファクタリングするフォルダを選びたい。フォルダの木から複数選べるフォームで聞いて」と送る。
2. フォームに木が表示され、推奨の項目があれば、その項目が見える所まで開いていることを確かめる。
3. 矢印キーで木を開閉して移動し、Spaceで2つのフォルダにチェックを付け、「送信」を押す。
4. Copilotが、チェックしたフォルダだけを対象に作業を進めることを確かめる。

### MAT-ANS-001 回答が同じ作業の流れで届く

検証: REQ-ANS-001, REQ-ANS-004

1. MAT-ASK-001 のフォームで、Tabキーで参加者数へ移り、矢印キーで値を変える。
2. ⌘/Ctrl+Enterを押す。
3. Copilotが新しい発言を待たずに、変えた値を使って続きを書くことを確かめる。

### MAT-ANS-002 キャンセル、値のない回答、コメント、補足

検証: REQ-ANS-003, REQ-ANS-005, REQ-ANS-006, REQ-ANS-007

1. 新しいチャットで MAT-ASK-001 の手順1を行い、フォームのボタンが「キャンセル」と「送信」の2つだけであることを確かめる。
2. 「キャンセル」を押す。パネルが閉じてチャットの入力欄にフォーカスが移り、Copilotが作業を区切って利用者の発言を待つことを確かめる。
3. もう一度新しいチャットで手順1を行い、参加費の入力欄を空にする。参加費の吹き出しのアイコンを押し、開いたコメント欄の下の定型文「他の要件を先に決める。」を押して「送信」を押す。
4. Copilotが参加費の値を決めつけずにほかの要件を先に決め、その後で参加費の質問をフォームで聞き直すことを確かめる。
5. もう一度新しいチャットで手順1を行い、形式の「選択を解除」を押して定型文「この質問の意味がわからない。説明が足りない。」を押し、イベント名の吹き出しのアイコンを押して「仮の名前」と書いて「送信」を押す。Copilotが形式の説明を足してフォームで聞き直し、イベント名を仮のものとして扱うことを確かめる。
6. 新しいチャットで MAT-ASK-002 の手順1を行い、保存先の「選択を解除」を押し、コメントに「答えない」と書く。「補足を書く」を開いて「保存先はSQLiteのファイルにしたい」と書き、「送信」を押す。
7. Copilotが保存先を聞き直さず、SQLiteのファイルに保存する前提で続きを書くことを確かめる。

### MAT-RES-001 回答後

検証: REQ-RES-001

1. MAT-ANS-001 で送信したとき、パネルが閉じることを確かめる。
2. Copilotが、変えた参加者数を利用者の判断として扱い、ほかの値を推奨を受け入れたものとして扱うことを確かめる。

### MAT-CANCEL-001 中断

検証: REQ-CANCEL-001, REQ-WAIT-001

1. MAT-ASK-001 の手順1を行い、フォームが表示されたら、ステータスバーに「Copilotが回答を待っています」が出ることを確かめる。
2. チャットの停止ボタンを押す。
3. パネルが閉じ、ステータスバーの表示が消えることを確かめる。

### MAT-WAIT-001 利用者が不在の設定

検証: REQ-WAIT-002

1. 設定`chat.autoReply`を有効にする。
2. MAT-ASK-001 の手順1を行う。フォームが出ず、Copilotが推奨の値で続きを書き、置いた前提を述べることを確かめる。
3. 設定を無効に戻す。VS Codeを再起動せずにもう一度手順1を行い、フォームが出ることを確かめる。

### MAT-WEB-001 web版

検証: REQ-WEB-001

1. GitHub Codespacesなど、サーバーにつないだweb版のVS Codeを開き、拡張機能をインストールして、Copilotにサインインする。
2. MAT-ASK-001 の手順1を行い、フォームがチャットの横のパネルに表示されることを確かめる。
3. 回答すると、パネルが閉じ、Copilotが続きを進めることを確かめる。

### MAT-PANEL-001 パネルの操作

検証: REQ-ANS-003, REQ-WAIT-001

1. MAT-ASK-001 の手順1を行い、送信せずにパネルを閉じる。Copilotが作業を区切り、ステータスバーの表示が消えることを確かめる。
2. もう一度手順1を行い、別のエディターのタブを前面に出す。ステータスバーの「Copilotが回答を待っています」を押し、フォームのパネルが前面に出ることを確かめる。
3. 「キャンセル」を押す。パネルが閉じ、チャットの入力欄にフォーカスが移ることを確かめる。

### MAT-ENV-002 Codexのハーネス

検証: REQ-ENV-002

1. チャットのセッションの対象(Session Target)で「Codex」を選ぶ。初回はSDKのダウンロードを求められるので、ダウンロードする。
2. MAT-ASK-001 の手順1を行い、フォームがチャットの横のパネルに表示されることを確かめる。
3. フォームが出てから5分以上待ってから送信する。パネルが閉じ、エージェントが回答の値で続きを進めることを確かめる。

### MAT-ENV-003 Agentsウィンドウ

検証: REQ-ENV-003

1. コマンド「Open Agents Window」でAgentsウィンドウを開く。
2. 既定のCopilotで、MAT-ASK-001 の手順1を行い、フォームがAgentsウィンドウの中のパネルに表示されることを確かめる。
3. 送信すると、パネルが閉じ、エージェントが回答の値で続きを進めることを確かめる。
4. 新しいセッションで対象を「Codex」に変え、既定のモデルのまま同じことを行う。

### MAT-LOOK-001 見た目と支援技術

検証: REQ-LOOK-001, REQ-A11Y-001

1. ライト、ダーク、ハイコントラストのテーマに切り替え、フォームがテーマの色で表示されることを確かめる。
2. スクリーンリーダーを有効にし、各項目のラベル、質問の説明、推奨の理由が読み上げられることを確かめる。

### MAT-PERF-001 起動とサイズ

検証: REQ-PERF-001

1. 「Developer: Show Running Extensions」を開き、Ask Formの起動時間を確かめる。
2. リリースの`.vsix`の大きさが、前のリリースから大きく増えていないことを確かめる。

### MAT-SEC-001 なりすましの防止

検証: REQ-SEC-001

1. `lsof -nP -iTCP -sTCP:LISTEN`などで、VS Codeの拡張機能ホストが待ち受けているポートを調べる。
2. Ask Formを無効にして同じように調べ、待ち受けるポートが変わらないこと、つまりAsk Formがポートを開かず、外から回答を送る口がないことを確かめる。

### MAT-DIST-001 リリースの配布

検証: REQ-DIST-001

1. [リリースの基準](../release.md)の配布条件を確認し、対象版、mainのCI結果、前回からの変更をリリースのPRかIssueに記録する。正式版では7日以上の配布期間、重大な不具合の報告と開いたIssueがないこと、実際のCopilotのモデルでデスクトップ版とweb版の手動受け入れを終えた結果も記録する。
2. タグのワークフローが成功し、GitHub Releasesに対象版の変更履歴、VSIX、SHA256SUMS.txtがあることを確認する。VSIXのSHA256と出所の証明を確認する。
3. 奇数minorにはpre-releaseの印があり、偶数minorにはないことを確認する。トークンを設定したMarketplaceとOpen VSXでも配布種別が一致し、インストールできることを確認する。
4. CIのVSIX成果物がZIPを解凍せずに利用でき、失敗時のtest-resultsがZIPで保存されることを確認する。

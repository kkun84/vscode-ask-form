# 手動受け入れ手順

偽のLLMによる自動受け入れテストに加えて、実際のCopilotの言語モデルでの振る舞いを人が確かめる手順です。リリースの前に、デスクトップ版のVS CodeでGitHub Copilotにサインインした状態で行います。各手順の「検証」に、確かめる要求を書きます。

## 準備

1. リリースする`.vsix`をインストールし、VS Codeを再起動する。
2. チャットをエージェントのモードにし、ツールの一覧で「Ask Form」が有効になっていることを確かめる。

## 手順

### MAT-ASK-001 フォームで質問される

検証: REQ-ASK-001, REQ-ASK-002, REQ-ASK-003

1. チャットに「来月の社内勉強会の参加費を決めたい。会場費は14万円。参加者数と参加費を変えながら収支を見たいので、フォームで聞いて」と送る。
2. チャットの中にフォームが表示され、各項目にAIの案が入り、その下に「AIの案: 」に続けて出どころが表示されることを確かめる。
3. 参加費を変えると、収支がすぐに変わることを確かめる。

### MAT-ASK-002 選んだ選択肢に応じて続きを聞かれる

検証: REQ-ASK-004

1. チャットに「TODOアプリの保存先を決めたい。ブラウザならlocalStorageかIndexedDBか、サーバーならポート番号とログインの要否も決めたいので、フォームで聞いて」と送る。
2. 保存先の選択肢の下に、選んだ保存先に関係する項目だけが表示されることを確かめる。
3. 保存先を「サーバー」に変えてポート番号を直して回答し、Copilotがブラウザの保存方式に触れず、サーバーの値で続きを書くことを確かめる。

### MAT-ANS-001 回答が同じ作業の流れで届く

検証: REQ-ANS-001, REQ-ANS-004

1. MAT-ASK-001 のフォームで、Tabキーで参加者数へ移り、矢印キーで値を変える。
2. ⌘/Ctrl+Enterを押す。
3. Copilotが新しい発言を待たずに、変えた値を使って続きを書くことを確かめる。

### MAT-ANS-002 AIに任せる、チャットで答える

検証: REQ-ANS-002, REQ-ANS-003

1. 新しいチャットで MAT-ASK-001 の手順1を行い、「AIに任せる」を押す。CopilotがAIの案のまま続けることを確かめる。
2. もう一度新しいチャットで手順1を行い、「チャットで答える」を押す。Copilotが作業を区切り、利用者の発言を待つことを確かめる。

### MAT-RES-001 要約と送り直し

検証: REQ-RES-001, REQ-RES-002, REQ-RES-003

1. MAT-ANS-001 のあと、フォームが要約になり、変えた項目に「あなたが変更」が付くことを確かめる。
2. 「変更して送り直す」を押し、何も変えないと送信ボタンが押せないことを確かめる。
3. 参加費を変えて「変更を送信」を押し、フォームのある会話の入力欄に差分の文章とJSON添付が入り、フォームに内容の確認と送信を促す案内が出ることを確かめる。まだチャットには送信されない。
4. 入力欄の下書きを消し、フォームを再編集する。同じ編集値のままボタンが押せ、元の回答の値に戻すと押せなくなることを確かめる。
5. 再び参加費を変えて下書きを置き、その会話の入力欄でEnterを押す。利用者の発言と値のJSONがCopilotに届くことを確かめる。
6. 別の会話にフォーカスを移しても自動送信されないこと、入力欄に置けない場合はフォームの会話を開いて入力欄を空にする案内が出ることを確かめる。

### MAT-CANCEL-001 中断

検証: REQ-CANCEL-001, REQ-WAIT-001

1. MAT-ASK-001 の手順1を行い、フォームが表示されたら、ステータスバーに「Copilotが回答を待っています」が出ることを確かめる。
2. チャットの停止ボタンを押す。
3. フォームが「キャンセルされました」になってボタンが消え、ステータスバーの表示が消えることを確かめる。

### MAT-WEB-001 web版

検証: REQ-WEB-001

1. vscode.devで拡張機能をインストールし、Copilotにサインインする。
2. MAT-ASK-001 の手順1を行い、フォームがチャットの横のパネルに表示されることを確かめる。
3. 回答すると、Copilotが続きを進めることを確かめる。

### MAT-LOOK-001 見た目と支援技術

検証: REQ-LOOK-001, REQ-A11Y-001

1. ライト、ダーク、ハイコントラストのテーマに切り替え、フォームがテーマの色で表示されることを確かめる。
2. スクリーンリーダーを有効にし、各項目のラベルと値の出どころが読み上げられることを確かめる。

### MAT-PERF-001 起動とサイズ

検証: REQ-PERF-001

1. 「Developer: Show Running Extensions」を開き、Ask Formの起動時間を確かめる。
2. リリースの`.vsix`の大きさが、前のリリースから大きく増えていないことを確かめる。

### MAT-SEC-001 なりすましの防止

検証: REQ-SEC-001

1. `lsof -nP -iTCP@127.0.0.1 -sTCP:LISTEN`などで、VS Codeの拡張機能ホストが待ち受けているポートを調べる。
2. トークンなしで`curl -X POST http://127.0.0.1:<port>/mcp`を送る。
3. 401が返ることを確かめる。

### MAT-DIST-001 リリースの配布

検証: REQ-DIST-001

1. [リリースの基準](../release.md)の配布条件を確認し、対象版、mainのCI結果、前回からの変更をリリースのPRかIssueに記録する。正式版では7日以上の配布期間、影響8以上の不具合の報告と開いたIssueがないこと、実際のCopilotのモデルでデスクトップ版とweb版の手動受け入れを終えた結果も記録する。
2. タグのワークフローが成功し、GitHub Releasesに対象版の変更履歴、VSIX、SHA256SUMS.txtがあることを確認する。VSIXのSHA256と出所の証明を確認する。
3. 奇数minorにはpre-releaseの印があり、偶数minorにはないことを確認する。トークンを設定したMarketplaceとOpen VSXでも配布種別が一致し、インストールできることを確認する。
4. CIのVSIX成果物がZIPを解凍せずに利用でき、失敗時のtest-resultsがZIPで保存されることを確認する。

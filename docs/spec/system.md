# システム仕様

拡張機能、質問のツール、フォーム画面が外から見てどう振る舞うかを定めます。各項目はシステムテスト(`test/system`)で検証します。拡張機能の項目は、配布物をVS Codeの代役の上で動かして検証します。

## フォームの設計図

### SPEC-FORM-001 設計図の形

AIはフォームを次の形のJSONで指定する。

| キー          | 型             | 必須 | 制約        |
| ------------- | -------------- | ---- | ----------- |
| `title`       | 文字列         | ○    | 1〜80文字   |
| `description` | 文字列         |      | 300文字以下 |
| `fields`      | 項目の配列     | ○    | 1〜40個     |
| `computed`    | 計算結果の配列 |      | 8個以下     |

項目は`type`で種類を区別し、すべての項目が次を持つ。

| キー            | 型         | 必須 | 制約                                                                 |
| --------------- | ---------- | ---- | -------------------------------------------------------------------- |
| `id`            | 文字列     | ○    | 英字か`_`で始まり、英数字と`_`だけの40文字以下                       |
| `label`         | 文字列     | ○    | 1〜60文字                                                            |
| `description`   | 文字列     |      | 質問が何を聞いているか。120文字以下                                  |
| `reason`        | 文字列     |      | 推奨の理由。選択肢以外の項目では値を決める助けになる助言。60文字以下 |
| `reasonDetails` | 文字列     |      | 推奨の詳しい理由。300文字以下                                        |
| `default`       | 種類による |      | 推奨する値                                                           |
| `when`          | 条件       |      | 項目を表示する条件。下記                                             |

AIは根拠を持って勧められるときだけ`default`を付ける。`reason`と`reasonDetails`は`default`のある項目にだけ付けられる。推奨のない質問の説明は`description`に書く。

種類ごとのキーは次のとおり。

| `type`         | キー                                                                                                                                                                                                         |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `text`         | `default`(500文字以下)、`placeholder`(80文字以下)、`multiline`                                                                                                                                               |
| `textList`     | `default`(1〜200文字の文字列の配列。20個以下)、`placeholder`(80文字以下)                                                                                                                                     |
| `number`       | `default`、必須の`min`と`max`、`step`(正の数)、`prefix`と`suffix`(各8文字以下)                                                                                                                               |
| `numberRange`  | `default`(`[下限, 上限]`)、必須の`min`と`max`、`step`(正の数)、`prefix`と`suffix`(各8文字以下)                                                                                                               |
| `date`         | `default`、`min`、`max`(どれも`YYYY-MM-DD`の文字列)                                                                                                                                                          |
| `time`         | `default`、`min`、`max`(どれも24時間の`HH:MM`の文字列)、`step`(1〜720の整数の分)                                                                                                                             |
| `choice`       | 必須の`options`(2〜6個。各`value`と`label`は1〜60文字、`description`は60文字以下、`details`は300文字以下)、`default`、`multiple`                                                                             |
| `searchChoice` | 必須の`options`(7〜100個。形は`choice`の選択肢と同じ)、`default`、`multiple`                                                                                                                                 |
| `treeChoice`   | 必須の`nodes`(1個以上の項目の配列。各項目は`value`(1〜200文字)、`label`(60文字以下)、`description`(60文字以下)、`children`(1個以上の項目の配列)。深さは4段まで)、`default`、`multiple`                       |
| `ranking`      | 必須の`options`(2〜8個。形は`choice`の選択肢と同じ)、`min`と`max`(順位に入れる数の下限と上限。1〜8で、既定は1と選択肢の数)、`default`(推奨する選択肢の`value`を推奨の順に、重複なく`min`〜`max`個並べた配列) |

どの項目も、表示する条件`when`を持てる。`when`は`field`と`anyOf`を持つ。

- `field`は、`fields`の中の`choice`か`searchChoice`の項目の`id`とする。前にあっても後ろにあってもよい。単一選択でも複数選択でもよい。
- `anyOf`は、`field`の項目の選択肢の`value`を、重複なく1個以上並べた配列とする。
- `when`のある項目は、`field`の項目が表示されていて、単一選択ならその値が`anyOf`のどれか、複数選択なら選んだ値のどれかが`anyOf`にある間だけ表示する。`field`の項目に値がなければ表示しない。`field`の項目自体が`when`で隠れていれば、その項目も隠れる。
- 表示されている項目を有効な項目と呼ぶ。
- `when`のある項目を続きの質問、`field`の項目を元の質問と呼ぶ。項目の表示の順は、`when`のない項目を`fields`の順に並べ、各項目のすぐ後ろにその続きの質問を`fields`の順に置いたものとする。続きの質問の後ろには、さらにその続きの質問を同じ規則で置く。続きの質問を`fields`のどこに書いても、元の質問との位置関係は変わらない。

計算結果は`id`、`label`、`expression`(300文字以下)と、任意の`prefix`、`suffix`、`decimals`(0〜4)、`primary`を持つ。

表示する文章の文字数は目安である。次のキーは、表の文字数の2倍まで受け付け、2倍を超えたら誤りとして返す。

- 設計図の`title`と`description`
- 項目の`label`、`description`、`reason`、`reasonDetails`、`placeholder`
- 選択肢の`label`、`description`、`details`
- 計算結果の`label`

AIは文字数を正確に数えられず、英語は同じ内容に日本語より多くの文字を使う。目安を少し超えただけの設計図を誤りとして返すと、AIが作り直す間、利用者が待たされる。

AIに示すJSON Schemaのオブジェクトには、すべて`additionalProperties: false`を書き、表にないキーを許さない。

AIに示すJSON Schemaには、これらのキーの`maxLength`として受け付ける上限を書き、目安は`description`に「Aim for 60 characters or fewer.」の形で書く。VS CodeのCopilotは、ツールを呼ぶ前にAIの入力をこのJSON Schemaで検査する。`maxLength`に目安を書くと、目安を1文字超えた設計図はAsk Formに届く前に拒否される。

`id`、選択肢の`value`、`default`、`expression`、`prefix`と`suffix`の文字数は目安ではなく上限であり、超えたら誤りとして返す。

- 項目と計算結果の`id`には、計算式の真偽値の予約語`true`と`false`を使えない。大文字と小文字は区別する。
- `__proto__`は有効な`id`として扱い、計算結果の表示と回答の`computed`にもその名前で保持する。

2〜6個の選択肢を説明付きで見比べる質問は`choice`、7個以上の候補から名前で探して選ぶ質問は`searchChoice`で聞く。見せ方は`type`で決まり、選択肢の数で暗黙に切り替えない。

派生元: REQ-ASK-001, REQ-ASK-002, REQ-ASK-003, REQ-ASK-004, REQ-ASK-005, REQ-ASK-006, REQ-ASK-007, REQ-ASK-008, REQ-ASK-009, REQ-ASK-010

### SPEC-FORM-002 設計図の意味的な検査

次のいずれかに当たる設計図は受け付けず、問題をすべて列挙して返す。

- SPEC-FORM-001 の表にないキーがある。設計図、項目、選択肢、木の項目、`when`、計算結果のどの階層でも受け付けず、`fields[0].options[0].fields`の形の場所とキーの名前を示す
- 項目と計算結果の`id`が重複している
- 数値項目で`min`が`max`以上、または`default`が範囲外
- 選択項目の選択肢の`value`が重複している
- 選択項目の`default`が選択肢にない、または`multiple`と`default`の形(単一か配列か)が合わない
- `default`のない項目に`reason`か`reasonDetails`がある
- 複数選択の`default`に同じ値が複数ある。空の配列や重複のない配列は受け付け、選んだ数と計算で使う数を一致させる
- 計算式が文法に合わない、または未定義の`id`や自分より後の計算結果を参照している
- `when`の`field`が、自分自身か未定義の`id`を参照している
- `when`の`field`をたどると循環し、`when`のない項目にたどり着かない
- `when`の`field`が参照する項目が`choice`でも`searchChoice`でもない
- `when`の`anyOf`に、参照する項目の選択肢にない値がある、または同じ値が複数ある
- 並べ替えの項目の選択肢の`value`が重複している、`min`と`max`が1≦`min`≦`max`≦選択肢の数を満たさない、または`default`が選択肢の`value`を重複なく`min`〜`max`個並べた配列でない
- `searchChoice`の項目で、選択肢の`value`が重複している、`default`が選択肢にない、または`multiple`と`default`の形が合わない
- 文字のリストの項目の`default`に同じ値が複数ある
- 範囲の項目で`min`が`max`以上、または`default`が`min`〜`max`の範囲の`[下限, 上限]`でない(下限が上限より大きいものを含む)
- 日付と時刻の項目の`default`、`min`、`max`が存在しない日付や時刻である、`min`が`max`以上である、`default`が範囲外である、または時刻の`default`が`step`の刻みに合わない。刻みは`min`から、`min`がなければ`00:00`から数える
- 木が4段より深い、木の項目の`value`が木全体で重複している、木の項目の合計が100個を超える、`default`が木にない、または`multiple`と`default`の形が合わない
- 複数選択の木の`default`に、祖先も`default`にある項目がある

派生元: REQ-ASK-001, REQ-ASK-004, REQ-ASK-005, REQ-ASK-006, REQ-ASK-007, REQ-ASK-008, REQ-ASK-009, REQ-ASK-010

### SPEC-EXPR-001 計算式

計算式は次を使える。評価できない場合(0での割り算など)の結果は「—」と表示する。

- 数値、`"`か`'`で囲んだ文字列、`true`、`false`
- 項目と、自分より前の計算結果の`id`。`when`で隠れている項目は未定義になる。数値項目は数値、単一選択は選んだ`value`、複数選択は選んだ数、文字列項目は文字列になる。並べ替えの項目は未定義になる。`searchChoice`の項目も、単一なら選んだ`value`、`multiple`なら選んだ数になる。文字のリストの項目は要素の数になる。範囲の項目は未定義になる。日付と時刻の項目は、`YYYY-MM-DD`と`HH:MM`の文字列になる。木の項目も、1つ選ぶなら選んだ`value`、複数選ぶなら選んだ数になる
- `+` `-` `*` `/` `%`、比較`<` `<=` `>` `>=` `==` `!=`、論理`&&` `||` `!`、条件`条件 ? 値 : 値`、かっこ
- 関数`min` `max` `abs` `floor` `ceil` `round`(`round(値, 桁数)`も可)

- `1e999`など有限でない数値リテラルは評価できないものとし、回答の計算結果は`null`になる。その値を使う比較や後続の計算結果も評価できない。短絡評価や条件分岐で使われない値は結果に影響しない。

派生元: REQ-ASK-003

## 質問のツール

### SPEC-TOOL-001 質問のツール

拡張機能は、デスクトップ版でも、サーバーにつないだweb版でも、AIから呼べるツールをVS Codeの言語モデルのツール(`languageModelTools`)として登録する。

- ツールの名前は`forms_ask_form`、チャットで参照する名前は`askForm`とする。常に有効にする。
- 入力は SPEC-FORM-001 の設計図とする。マニフェストの`inputSchema`と`modelDescription`は、拡張機能の設計図のSchemaとツールの説明から作る。
- ツールの説明は、利用者に何かを聞くときは、組み込みの質問ツール(`askQuestions`、`ask_user`、`AskUserQuestion`、`request_user_input`)やチャットの文章での質問より、このツールを使うよう求める。1つの選択だけでもこのツールを使う。
- 呼ばれると、フォームをチャットの横のパネルに表示して回答を待つ(SPEC-EXT-004)。
- 拡張機能はMCPサーバーを提供しない。VS Codeのハーネスは、MCPのツール呼び出しを1分から5分の上限で打ち切り、それより長く考えた利用者の回答を捨てるためである。言語モデルのツールの呼び出しは、CopilotとCodexのハーネスでは打ち切られない。
- VS Code 1.146と1.147では、ハーネスとウィンドウによってツールの扱いが違う。
  - CopilotとCodexは、メインウィンドウでもAgentsウィンドウでもツールを呼び、フォームはそのウィンドウのパネルに出る。
  - Agentsウィンドウは、マニフェストの`capabilities.agentsWindow.supported`で対応を宣言した拡張機能だけを動かす。拡張機能はこれを`true`と宣言する。宣言が無いと、インストールした拡張機能はAgentsウィンドウで動かず、そのセッションにツールが渡らない。開発用のパスで読み込んだ拡張機能は、この制限を受けない。
  - Copilotは、GPT-5.xやCopilot Fusionなど多くのモデルで、拡張機能のツールを最初のツールの一覧に入れず、名前だけを伝える。モデルが`tool_search_tool`で検索した後に、ツールの定義を読み込む。
  - Codexは、新しいモデル(GPT-6.1-Solなど。Agentsウィンドウの既定)では、ツールをJavaScriptを実行するツール`exec`の中から呼ぶ(コードモード)。このときも結果は同じに返る。
  - Claudeは、ツールを呼んでも、VS Codeが拡張機能の`prepareInvocation`の後に`invoke`を呼ばずに止まるので、フォームが出ない。

派生元: REQ-ASK-001, REQ-ANS-001, REQ-ENV-002, REQ-ENV-003

### SPEC-TOOL-003 回答を待つ

ツールは、画面から結果が届くまで結果を返さない。結果は次のいずれかで、AIへの指示の文章の後に、結果のJSONを付けて返す。

| `status`         | 意味                             | ほかのキー                                                                    |
| ---------------- | -------------------------------- | ----------------------------------------------------------------------------- |
| `submitted`      | 送信した                         | `values`、`held`、`changedByUser`、`computed`、`comments`、`heldForm`、`note` |
| `answer_in_chat` | キャンセルした。チャットで答える | なし                                                                          |
| `unavailable`    | 利用者が不在の設定で、質問しない | なし                                                                          |

- `values`には、有効な項目のうち、値のある項目だけを入れる。`when`で隠れている項目は入れない。
- 空欄のまま送信した文字列の項目は、空文字列を値として`values`に入れる。
- `held`には、値のない有効な項目の`id`を表示の順(SPEC-FORM-001)に入れる。値のない項目は`values`に入れない。`when`で隠れている項目は、`values`にも`held`にも入れない。
- `heldForm`には、`held`の項目の設計図を、表示の順に、題名と`fields`の形で入れる。AIはこれを元にこのツールで聞き直せる。`held`にない項目を参照する`when`は外す。`held`が空なら`heldForm`のキーを入れない。
- `changedByUser`には、`values`に入る項目のうち、推奨と違う値にした項目と、推奨がなく利用者が答えた項目の`id`を入れる。
- 値のない項目を参照する計算結果は`null`になる。
- `comments`には、利用者が有効な項目に書いたコメントを、項目の`id`から文章への対応で入れる。前後の空白を除き、空のコメントは入れない。`when`で隠れている項目のコメントは入れない。コメントがなければ`comments`のキーを入れない。
- `note`には、利用者が書いた補足を、前後の空白を除いて入れる。補足が空なら`note`のキーを入れない。

AIへの指示の文章は、AIが次にすべきことを書く。`submitted`の指示には、空文字列は利用者が意図して空欄にした答えであること、`comments`の各コメントをその項目に当てはめ、値と食い違えばコメントに従うことを指示する。`held`の項目には、コメントが任せるならAIが値を決めて何を選んだかを伝え、コメントが不要と言うならその質問を捨て、それ以外は値を決めつけずにその値に依存しない作業を進め、必要になったら`heldForm`を元に聞き直すよう指示する。`note`があるときは、食い違う値より補足に従い、補足が`held`の項目に答えていればそれを使うよう指示する。`answer_in_chat`の指示には、作業を区切って利用者の発言を待つよう指示する。

利用者が不在の設定(SPEC-EXT-007)のとき、ツールは設計図を検査した後、待たずに`unavailable`を返し、パネルも待機の表示も出さない。`unavailable`の指示には、聞き直さず、推奨した値で進め、推奨のない質問は自分で判断し、置いた前提を利用者に伝えるよう指示する。設計図に誤りがあれば、不在の設定でも SPEC-TOOL-004 の誤りを返す。

待っている間に利用者が不在になったときも、ツールは待つのをやめて`unavailable`を返し、パネルを閉じる。

- 複数選択の差分は並び順を無視し、値ごとに比べる。値にNUL文字があっても、異なる選択は`changedByUser`に含める。

派生元: REQ-ANS-001, REQ-ANS-003, REQ-ANS-005, REQ-ANS-006, REQ-ASK-004, REQ-WAIT-002

### SPEC-TOOL-004 設計図の誤り

ツールは SPEC-FORM-001 または SPEC-FORM-002 に反する設計図を受け取ると、パネルを開かずに誤りとして返し、AIが直せるよう問題の一覧を示す。

派生元: REQ-ASK-001

### SPEC-TOOL-005 画面からの回答

画面は、パネルのホストに`tools/call`で`form_answer`を送って回答する。

- 入力は、フォームの鍵、操作(`submit`、`chat`)、`values`、`held`、`comments`、`note`
- パネルのホストは、そのパネルのフォームの鍵と一致し、まだ回答も中断もされていなければ、回答を検査してツールの結果にする
- `values`を設計図に照らして検査し、合わなければ誤りを返す
- 有効な項目のうち`values`に値がない項目は、`held`に`id`があり、`comments`にコメントがなければ誤りを返す。値のある項目や有効でない項目を`held`に入れた場合も誤りを返す
- `comments`が項目の`id`から文字列への対応でないか、有効でない項目へのコメントか、500文字を超えるコメントがあれば誤りを返す
- 複数選択の回答に同じ値が複数あれば拒否し、画面の選択数と計算結果が食い違う値を受け付けない。木の項目の回答も同じに扱い、木にない`value`を拒否する
- 並べ替えの回答は、選択肢の`value`を重複なく`min`〜`max`個並べた配列でなければ誤りを返す
- `searchChoice`の回答は、`choice`と同じく、単一なら選択肢のどれか、`multiple`なら重複のない選択肢の配列でなければ誤りを返す
- 文字のリストの回答は、空白だけでない200文字以下の文字列を、重複なく20個まで並べた配列でなければ誤りを返す
- 範囲の回答は、`min`〜`max`の範囲の2つの数値で、下限が上限以下でなければ誤りを返す
- 日付と時刻の回答が、存在しない日付や時刻か、範囲外か、時刻の`step`の刻みに合わなければ誤りを返す
- `note`が文字列でないか、2000文字を超えていれば誤りを返す
- 鍵が一致しないか、回答済みか中断済みなら、受け付けられないことを示す誤りを返す

派生元: REQ-ANS-001, REQ-ANS-005, REQ-ANS-006, REQ-ANS-007, REQ-CANCEL-001, REQ-ASK-005, REQ-ASK-006, REQ-ASK-007, REQ-ASK-008, REQ-ASK-009, REQ-ASK-010

### SPEC-TOOL-006 フォームの鍵

フォームの鍵は、ツールが受け取った引数をそのまま正規化したJSONから決まる。キーの順序が違うだけの引数からは同じ鍵が得られ、画面とパネルのホストで同じ鍵になる。

派生元: REQ-ANS-001

### SPEC-TOOL-007 中断

ツールの呼び出しが取り消されると、その質問は中断になり、以後の`form_answer`は SPEC-TOOL-005 の誤りになる。取り消しは対象の質問だけを終わらせ、ほかの質問は待機を続ける。

派生元: REQ-CANCEL-001

### SPEC-TOOL-010 画面の設定

## フォームの画面

### SPEC-UI-001 初期表示

画面は質問ごとに、質問名、質問の説明、入力欄か選択肢を表示する。`default`があれば、その値で始める。

- 選択肢には`description`と`details`を表示する。`default`の選択肢には「推奨」の印を付け、その選択肢の中に推奨の理由(`reason`と`reasonDetails`)を表示する。
- 選択肢でない項目に`default`があれば、値が推奨のままの間、見出しの右に「推奨」の札を出す。`reason`か`reasonDetails`があれば、入力欄の下に推奨する値と理由を表示する。理由がなければ、推奨のままの間はこの表示を出さない。入力欄と同じ値を繰り返すだけになるため。利用者が値を変えたら、札を消し、推奨する値と「推奨に戻す」を表示する。押すと推奨の値に戻して入力欄にフォーカスを戻す。隠している間の推奨の表示は、読み上げの説明にも入れない。
- `default`のない単一選択と数値の項目は、未回答で始める。先頭の選択肢や`min`を初期値にしない。見出しに「未回答」と示す。未回答の項目が残る間は送信できず、送信しようとしたら、その項目を無効と示し、最初の未回答の項目にフォーカスを移す。未回答の項目は、答えるか、コメント(SPEC-UI-012)を書くと送信できる。
- 未回答の項目が残る間、「送信」の左に「未回答 2問」の形で残りの数をボタンで示す。押すたびに、次の未回答の項目の入力欄へフォーカスを移し、最後の次は最初へ戻る。送信しようとして止めた後は、誤りの色で示す。未回答の項目がなくなれば消す。
- `default`のない文字列の項目は空欄で、複数選択の項目は何も選ばれていない状態で始める。どちらもそのまま送信でき、空欄や選択なしという答えになる。
- フォームは幅720pxまでとし、それより広いパネルでは中央に置く。1行が長くなりすぎて読みにくくなるのを防ぐため。
- 選択肢は1つずつ枠で囲み、選んだ選択肢は枠と背景を強調の色にする。推奨の値と理由は、印を付けた1行にまとめ、収まらなければ折り返す。
- 質問の間に区切り線を引き、質問名の左端を入力欄の左端とそろえる。どこからどこまでが1つの質問かを、見出しの字下げで誤解させないため。
- 質問は詳しい説明(`details`と推奨の理由)を畳める。最初は開いている。見出しの右、コメントのボタンの左に「詳細」と書いた開閉のボタンを置き、このボタンでだけ開閉する。読み上げでは「形式の詳細」のように質問名を含めて読む。選択肢を選んでも、質問名を押しても、質問の中にフォーカスを移しても開閉しない。押した直後に下の質問が動いたり、読んでいる説明が消えたりしないようにするため。畳む対象がない質問には開閉のボタンを出さない。理由のない推奨だけを持つ質問も、畳む対象がないものとする。
- 数値の項目は、スライダーと入力欄で答える。入力欄は、増減ボタン、左右へのドラッグ、フォーカス中のホイールでも値を変えられ、Shiftを押すと大きく変わる。確定した値は範囲に収め、桁を区切って表示する。入力欄はスピンボタンとして読み上げる。
- 1行の文字列の項目には、中身を空にするボタンを出す。
- 開閉、条件付きの質問の現れ、選んだ行の色の変化には短い動きを付ける。動きを減らす設定のときは付けない。
- 複数選択の値にNUL文字があっても異なる選択への変更を検出する。並び順だけの違いは変更と扱わない。

派生元: REQ-ASK-002

### SPEC-UI-003 回答の操作

ボタンの行は、フォームがパネルより長い間、パネルの下端に留める。どこまでスクロールしていても送信でき、未回答の数(SPEC-UI-001)も見える。行の下に質問が隠れている間は、行の上に影を出す。フォーカスを移した先がボタンの行に隠れないよう、スクロールの止まる位置に行の分の余白を取る。

### SPEC-UI-011 条件付きの項目

画面は、項目を表示の順(SPEC-FORM-001)に並べ、続きの質問もほかの質問と同じ形で、字下げせずに表示する。`when`の条件を満たさない間は、その質問を隠す。

- 質問の間の区切り線は、表示されている質問の間にだけ引く。隠れた質問のために、区切り線を重ねたり、先頭の質問の上に引いたりしない。
- 選択を切り替えて質問が隠れても、直した値をフォームを閉じるまで覚えておき、また表示されたらその値で表示する。回答には、表示されている質問だけを使う。
- 質問の中にフォーカスがあるときにその質問が隠れたら、フォーカスを条件の元の質問に移す。
- 条件の元の質問の選択を解除すると、その質問を条件とする質問を隠す。

続きの質問のあるフォームでは、質問の左に余白を設け、どの答えがどの質問を出しているかを線で示す。線は装飾として支援技術から隠し、同じ内容を文章で伝える。

- 続きの質問を持つ質問が表示されている間、その質問の段ごとに1本の縦の筋を余白に置く。続きの質問の続きの質問の筋は、1段右に置く。
- 選ぶと続きの質問が現れる選択肢の行には、選択肢の枠の左の縁に点を置く。選んでいない選択肢の点は中を抜き、選んで続きの質問を出している選択肢の点は塗る。
- 候補を絞り込んで選ぶ質問で、選んだ選択肢が一覧のスクロールか絞り込みで見えない時は、その選択肢の点を「選んだもの」の行の高さに置く。見えない選んでいない選択肢には、点を置かない。
- 選んで続きの質問を出している選択肢の点から筋へ線を引き、そのうち一番上の選択肢から、表示されている最後の続きの質問まで筋を引き、筋から表示されている各続きの質問の見出しへ線を引く。線の曲がり角はすべて丸め、選択肢から出る線は左から下へ、続きの質問へ入る線は下から右へ曲げる。
- 表示されている続きの質問の見出しの横に、その質問を出している答えの名前を小さな札で示す。1つ選ぶ質問の答えには丸、複数選ぶ質問の答えには四角の印を付ける。見出しの横に収まらない幅では、札を見出しの下の行に回す。
- 続きの質問にカーソルを乗せるか、質問の中にフォーカスがある間は、その質問を出している選択肢から見出しまでの線を強調の色で上に重ね、その選択肢の行と札を強調し、ほかの線を薄くする。
- 続きの質問には、「「ログインの方式」で「社内SSO」を選んだので表示」の形の説明を支援技術に伝える。元の質問が複数選択なら「チェックを入れた」とし、答えが複数なら「」と「」でつなぐ。続きの質問を出す選択肢には、「選ぶと質問が2個増えます」の形の説明を伝える。
- 値の変更、質問の表示と非表示、大きさの変化、フォントの読み込みのたびに線を引き直す。線と強調の色はVS Codeのテーマの色を使い、ハイコントラストのテーマでは`contrastBorder`と`contrastActiveBorder`の色を使う。

派生元: REQ-ASK-004

### SPEC-UI-012 値のない回答

画面は、どの質問も、値を答えずにコメントだけで送れるようにする。

- 単一選択の質問では、何かが選ばれている間、見出しの右、コメントのボタンの左に「選択を解除」を出す。選択肢の下に置くと、めったに使わない操作のために質問ごとに1行を使うため。読み上げでは「形式の選択を解除」のように質問名を含めて読む。押すと選択を外し、コメント欄を開いてフォーカスを移す。
- 数値の質問では、入力欄を空にして確定すると値を外す。
- 文字列の質問と複数選択の質問には値を外す手段を出さない。空欄の文字列と、何も選ばない複数選択は、それぞれ空欄と「なし」という答えになる。答えない意図はコメントで伝える。
- 値がない間は見出しに「回答なし」と示す。
- 値を入れるか選択肢を選ぶと、値のある回答に戻る。
- 文字列の項目を手で空欄にしたときは、値を外したとは扱わず、空欄という答えとして送る。
- 値もコメントもない質問は未回答とし、送信できない。
- 計算結果のうち値のない質問を参照するものは「—」と表示する。
- 送信すると、値のない質問を`held`として渡す(SPEC-TOOL-005)。

派生元: REQ-ANS-005

### SPEC-UI-013 補足

回答の画面は、質問と計算結果の後、ボタンの前に、閉じた「補足を書く」を持つ。

- 開くと、複数行の入力欄と、「選択肢にない答えや、Copilotに伝えたいことを書けます。回答と一緒に届きます。」の案内を表示する。フォームの縦の長さを増やさないため、最初は閉じておく。
- 入力欄は2000文字までしか受け付けない。送信してから長すぎると分かる事がないようにする。ブラウザによる文字の数え方の違いに左右されないよう、入力のたびに画面でも長さを確かめて切り詰める。
- 送信すると、入力欄の文章を`note`として渡す(SPEC-TOOL-005)。入力欄で⌘/Ctrl+Enterを押しても送信できる。
- 補足を書いても、未回答の質問が残る間は送信できない。答えが選択肢にない質問は、値を外して、その質問のコメント(SPEC-UI-014)か補足に答えを書く。

### SPEC-UI-014 項目ごとのコメント

画面は、どの質問にも、その質問へのコメントを書く手段を持たせる。値だけ、コメントだけ、値とコメントの両方のどれでも送れる。

- 見出しの右端に、文字のない吹き出しのアイコンのボタンを出す。読み上げとツールチップでは「件数へのコメント」のように質問名を含めて示す。コメント欄は畳んだ状態で始め、フォームの縦の長さを増やさない。
- ボタンを押すと、その質問の下に、左に色の付いた縦線と吹き出しのアイコンつきの「コメント」の見出しを持つ囲みを開き、2行の入力欄と定型文を出して入力欄にフォーカスを移す。回答の入力欄や推奨の囲み、選択肢と見分けられるよう、入力欄は点線の枠で背景を付けず、定型文は「+」を前に付けた文字のボタンにする。もう一度押すと畳む。畳んでもコメントは残り、コメントのある質問ではアイコンの色を変えて示す。
- 入力欄は500文字までしか受け付けない。
- 入力欄の案内は、値のある質問では「この質問について、Copilotに伝えたいことを書けます。」とし、値のない質問では、答えない理由や、あとで聞いてほしいか、Copilotに決めてほしいかを書くよう促す。
- 入力欄の下に定型文のボタンを並べる。押すと、空のコメントにはその文を入れ、書きかけのコメントには後ろに足す。書きかけの末尾が日本語の文字なら空白を挟まず、それ以外なら空白を挟む。定型文は、設定`askForm.commentPresets`(文字列の配列)の項目を使う。設定の既定値は「他の要件を先に決める。」「この質問の意味がわからない。説明が足りない。」「インターネットで調査した上でもう一度検討しよう。」で、設定画面で項目を足したり消したりできる。項目がなければ定型文を出さない。設定を読めないときは、表示の言語の同じ3つの文を使う。画面は設定をSPEC-TOOL-010で受け取る。
- 送信すると、コメントを`comments`として渡す(SPEC-TOOL-005)。

派生元: REQ-ANS-007

### SPEC-UI-015 並べ替え

画面は、並べ替えの項目を、順位の置き場と候補の置き場の2つに分けて表示する。利用者は候補から順位へ選択肢を移し、移した順に順位を付ける。

- 順位の置き場の各行には、順位の数と、選択肢の`label`、`description`、`details`を表示する。候補の置き場は、設計図の選択肢の順に並べる。順位が空の間は、置き場に「候補を押すと、ここに順に入ります」と示す。
- 候補を押すと、順位の末尾に入る。順位の行の「×」を押すと、候補の元の位置に戻る。行はポインターでドラッグして、順位の中で動かしたり、候補と順位の間で移したりできる。キーボードでは、候補でEnterを押すと順位の末尾に入り、SpaceかEnterで持ち上げて↑↓で動かし、←→で順位と候補を移り、もう一度押して置く。Escで元の位置に戻し、順位の行でDeleteを押すと候補に戻す。持ち上げ、移動、置く、戻すたびに、どちらの置き場の何番目かを表示の言語で読み上げる。
- 操作方法の説明文は画面に出さない。キーボードでの操作方法は、各行の読み上げの説明としてだけ渡す。
- 順位に入れられるのは`max`個までで、上限に達すると候補から順位へ移せない。
- `default`があれば、推奨の選択肢を推奨の順で順位に入れて始め、推奨の順と理由を表示する。順位を変えたら「推奨に戻す」を出す。
- `default`がなければ、順位を空で始める。順位に`min`個以上入るまで未回答とする。順位に何か入れたら「リセット」を出し、押すと空に戻す。
- 回答の値は、順位の置き場の選択肢の`value`を上から順に並べた配列にする。候補に残った選択肢は回答に入れない。

派生元: REQ-ASK-005

### SPEC-UI-016 候補の絞り込み

画面は、`searchChoice`の項目を、絞り込みの入力欄と、`choice`と同じラジオボタンかチェックボックスの一覧で表示する。

- 入力欄の読み上げは「主な言語を絞り込む」のように質問名を含める。右に「表示数 / 全数」を出す。
- 入力欄に文字を打つと、`label`か`description`にその文字を含む選択肢だけを一覧に出す。大文字と小文字は区別しない。一致が無ければ「一致する選択肢がありません」と出す。入力欄で↓を押すと、見えている最初の選択肢にフォーカスを移す。矢印キーでの移動は、隠れた選択肢を飛ばす。
- 一覧は枠で囲み、約6行の高さでスクロールする。選んだ選択肢は一覧に残り、チェックが付く。絞り込みで隠れても分かるよう、一覧の下に「選んだもの：」と選んだ選択肢の`label`を出す。何も無ければ「なし」と出す。
- 選択肢の`description`と推奨の理由は1行で切り、選んだ選択肢では全文を出す。`details`は選んだ選択肢でだけ出す。
- 単一の項目は、何かを選んでいる間、見出しの右に「選択を解除」を出す(SPEC-UI-012)。`default`がなければ未回答で始める(SPEC-UI-001の単一選択と同じ扱い)。
- `multiple`の項目は、何も選ばずに送信でき、選択なしという答えになる。
- `default`があれば、推奨の選択肢に「推奨」の印と理由を出す(`choice`と同じ)。

派生元: REQ-ASK-006

### SPEC-UI-017 文字のリスト

画面は、文字のリストの項目を、値を1つずつ丸い札で並べる入力欄で表示する。

- 欄に書いてEnterを押すと、前後の空白を除いた文字を値として足す。足した値は札になり、札の×かBackspaceで消せる。
- 既にある値、200文字を超える値、21個目の値は足さず、欄の下に理由を表示する。理由は読み上げる。
- 書きかけの文字は、欄からフォーカスが外れた時と、⌘/Ctrl+Enterで送信する前に足す。
- `default`があれば、その値を並べて始め、推奨の値と理由を表示する。値を変えたら「推奨に戻す」を出す。`default`がなければ空で始め、そのまま送れる。空のリストは、何も無いという答えになる。
- 回答の値は、札の順に並べた文字列の配列にする。並び順だけの違いは変更と扱わない。

派生元: REQ-ASK-007

### SPEC-UI-018 数値の範囲

画面は、範囲の項目を、つまみ2つのスライダーと、下限と上限の数値の欄で答えさせる。

- 数値の欄は、数値の項目と同じく、増減ボタン、左右へのドラッグ、フォーカス中のホイール、Shiftでの大きな増減を持ち、スピンボタンとして読み上げる。つまみと欄は「予算の下限」「予算の上限」のように質問名を含めて読む。
- スライダーと数値の欄は同じ値を示し、どちらで変えてももう一方が追従する。
- つまみ同士はすれ違わない。数値の欄で下限に上限より大きい値を確定すると上限と同じ値に、上限に下限より小さい値を確定すると下限と同じ値にする。範囲の外の値は範囲に収める。
- `default`があれば、その範囲で始め、推奨の範囲と理由を表示する。値を変えたら「推奨に戻す」を出す。
- `default`がなければ未回答で始め、つまみを隠し、欄を空にする。つまみを動かすか欄に値を確定すると回答になる。下限か上限の欄を空にして確定すると、未回答に戻す。
- 回答の値は`[下限, 上限]`にする。

派生元: REQ-ASK-008

### SPEC-UI-019 日付と時刻

画面は、日付の項目を、入力欄とカレンダーを開くボタンで答えさせ、時刻の項目を、時と分の欄で答えさせる。

- 日付の欄は、ホストのロケールの形で日付を表示し、同じ形で入力を受け付ける。Enterか、フォーカスが外れた時に確定する。ボタンは「リリース日のカレンダーを開く」のように質問名を含めて読む。
- カレンダーは、矢印キーで日を動かし、Enterで選ぶと閉じる。`min`と`max`の外の日は選べない。カレンダーはパネルの中に重ねて出す。
- 時刻の欄は、時と分をそれぞれスピンボタンとして読み、数字の入力と↑↓で値を変える。値は24時間の形で扱う。`step`があれば、入力した時刻を範囲の中の最も近い刻みに丸める。
- `default`があれば、その値で始め、推奨の値と理由を表示する。値を変えたら「推奨に戻す」を出す。`default`がなければ未回答で始める。
- 欄を空にすると、値のない回答になる(SPEC-UI-012)。

派生元: REQ-ASK-009

### SPEC-UI-020 木から選ぶ

画面は、木の項目を、枝を開閉できる木として表示する。

- 各行に`label`と`description`を表示する。枝には開閉のしるしを付ける。枝も葉も選べる。
- 最初は、推奨の値の祖先の枝だけを開く。推奨がなければ、最上位の項目だけを見せる。
- 木は1つのタブ位置を持つ。↑↓で見えている行を移動し、→で枝を開くか最初の子へ、←で枝を閉じるか親へ移る。Home、Endで先頭と末尾へ移る。文字を打つと、その文字で始まる行へ移る。
- `multiple`がなければ、行を押すか、SpaceかEnterで、その行を選ぶ。開閉のしるしを押すと、選ばずに開閉する。何かが選ばれている間、見出しの右に「選択を解除」を出し、押すと選択を外してコメント欄を開く(SPEC-UI-012)。推奨がなければ未回答で始める。
- `multiple`なら、各行にチェックボックスを出す。行を押すか、SpaceかEnterでチェックを切り替える。枝をチェックすると、その下のすべての項目もチェックし、一部だけチェックされた枝は混在の印を出す。回答には、すべてチェックされた最も外側の項目の`value`を入れる。何もチェックしない回答も送れる。
- 推奨と違う値にすると「推奨に戻す」を出す。
- 各行は、その行の`label`と`description`だけを名前に持つ木の項目とする。子の行は枝の要素の中に入れず、階層と兄弟の中の位置を`aria-level`、`aria-posinset`、`aria-setsize`で伝え、閉じた枝の下の行は隠す。開いた枝の名前は、見えている子の行の文字を含まないので、見えている文字と名前が食い違わない。

派生元: REQ-ASK-010

### SPEC-UI-010 画面への通知の送り主

- 初期化への応答、設計図(`ui/notifications/tool-input`)、ホストの表示設定(`ui/notifications/host-context-changed`)、呼び出しへの返答は接続先のホストからだけ受け付ける。別のウィンドウやフレームから届いたメッセージで画面を変えない。
- ホストのoriginが分かる場合は一致も検査する。直接読めない場合は、そのホストから最初に受け付けたJSON-RPCのoriginを保持し、以後異なるoriginを拒否する。

派生元: REQ-SEC-001

## 拡張機能

### SPEC-EXT-002 待機の表示

回答を待つフォームが1つ以上ある間、ステータスバーに「Copilotが回答を待っています」を表示する。

- 表示を押すと、回答を待つフォームのパネルを前面に出す。複数あれば、先に待ち始めたフォームを出す。チャットにはフォームがないので、チャットを開いても利用者はフォームにたどり着けない。

派生元: REQ-WAIT-001

### SPEC-EXT-004 パネルのフォーム

質問のツール(SPEC-TOOL-001)が呼ばれると、拡張機能はフォームをエディター横のパネルに表示して回答を待つ。デスクトップ版と、サーバーにつないだweb版で同じに振る舞う。

- チャットの停止でツールの呼び出しが取り消されたら、パネルを閉じる。読み込み中でも閉じる。回答できないパネルを残さない。チャットは開かない。
- 閉じたパネルには何も送らない。パネルはこのように必ず閉じるので、画面に回答後や中断後の表示を持たせない。
- 送信せずにパネルを閉じたら、「キャンセル」と同じ`answer_in_chat`を結果として返し、回答待ちの表示を消す。
- 「送信」を押したら、結果を返してパネルを閉じる。質問のたびに回答済みのパネルがタブとして残り、利用者が自分で閉じることになるのを避ける。フォーカスは、VS Codeがパネルを閉じたときに戻す場所に任せる。
- 「キャンセル」を押したら、パネルを閉じてチャットを開き、入力欄にフォーカスを移す。利用者はチャットで答えると決めたので、役目を終えたパネルを残さない。チャットを開けない環境でも、結果を返してパネルを閉じる。

派生元: REQ-ASK-001, REQ-WEB-001, REQ-CANCEL-001, REQ-RES-001

### SPEC-EXT-007 利用者が不在の設定

VS Codeの設定`chat.autoReply`が有効な間、拡張機能は利用者が不在であるとみなす。VS Codeの組み込みの質問ツールは、この設定が有効なら質問せずに進める。フォームも同じ設定に従う。

- 設定はツールが呼ばれるたびに読む。VS Codeを再起動しなくても、設定の変更が次の質問から効く。
- この設定が有効な間、ツールはパネルを開かず、待機の表示も出さずに、`unavailable`の結果を返す。
- フォームが回答を待っている間に設定が有効になったら、パネルを閉じて`unavailable`を返す。VS Codeの組み込みの質問ツールも、待っている質問を同じように省く。

派生元: REQ-WAIT-002

### SPEC-EXT-005 起動・サイズ・検査の予算

拡張機能はVS Codeの起動完了後に読み込まれる。バンドルの読み込みと起動処理は`budgets.json`の`activationMs`以内に終わり、各バンドルの大きさは`budgets.json`の`size`の上限を超えない。

- `timed.ts`による検査は`budgets.json`の時間を超えたら終了を要求し、1秒の猶予後に強制終了して失敗とする。受け入れテストを含む子と孫を同じプロセスグループで止め、直下の子だけが先に終了しても強制終了を取り消さない。Windowsではプロセスツリーを終了する。

派生元: REQ-PERF-001

## リリース

### SPEC-REL-001 配布前の検査と公開

- mainへのpushで動いたCIが成功したとき、またはworkflow_dispatchで開始する。対象のコミットがその時点のmainの先頭でなければ何もしない。originに`v<version>`がなければ対象のコミットにタグとリリースを作る。既存なら、CHANGELOG.mdの`## 未リリース`に項目があるときだけ、版数を上げるコミットを`release/next`ブランチにforce pushし、mainへのリリースPRを作るか更新して、auto-mergeを設定する。リリースPRはGitHub Appのトークンで作り、PRとマージ後のmainでCIを動かす。タグの照会失敗時は公開しない。同時に複数のリリースを実行せず、実行中のリリースを取り消さない。
- 版数を上げるとき、minorが奇数ならpatchを1つ上げ、偶数なら次の奇数のminorの`.0`にする。CHANGELOG.mdの`## 未リリース`を新しい版の見出しに書き換え、その上に空の`## 未リリース`を置く。

- タグはpackage.jsonのversionに`v`を付けたものと一致し、版数は先頭の余分な0や接尾辞のない`major.minor.patch`とする。CHANGELOG.mdの`## <version>`の項には空でない箇条書きが1つ以上必要で、不備があれば公開を止める。
- minorが奇数ならプレリリース、偶数なら正式リリースとする。検査CLIは判定をGITHUB_OUTPUTがあれば追記し、なければ標準出力に出す。任意の第2引数で指定したファイルに対象版の本文だけを書き出す。
- リリースは検査とテスト後にVSIXを作り、その版の変更履歴を説明としてGitHub ReleasesへSHA256SUMS.txtとともに公開し、VSIXの出所を証明する。トークンがある配布先だけ追加公開し、各配布先へプレリリースの指定を渡す。
- CIのVSIX成果物は単一ファイルをZIPに包まず保存し、test-resultsはZIPを維持する。

派生元: REQ-DIST-001

### SPEC-REL-002 変更履歴の項目の検査

- `## 未リリース`の項目は、`### 追加`、`### 変更`、`### 非推奨`、`### 削除`、`### 修正`、`### セキュリティ`のいずれかの見出しの下に置く。`pnpm lint`は、`## 未リリース`が無いか、見出しの無い項目か、他の見出しがあれば失敗する。
- PRで`src/`が変わり、`no-changelog`ラベルが無く、`## 未リリース`にPRの基点に無い項目が無ければ、PRの検査を失敗にする。ラベルの付け外しで検査をやり直す。

派生元: REQ-DIST-001

### SPEC-REL-003 画像と紹介動画の撮り直しの検査

READMEの画像(`docs/images`)と紹介動画(`docs/media`)は、利用者がMarketplaceやGitHubで最初に見るものなので、画面や振る舞いと食い違わないようにする。

- PRで、フォームの画面、拡張機能、画面の文言、撮影の台本(`src/ui`、`src/extension`、`src/core/messages.ts`、`test/acceptance`の撮影と演出、撮影に使う設計図、`scripts/pv.ts`)のどれかが変わり、`docs/images`と`docs/media`のどちらも変わっておらず、`no-media`ラベルが無ければ、PRの検査を失敗にする。ラベルの付け外しで検査をやり直す。
- pushの前のフックでも、`origin/main`との差で同じ検査をする。撮り直しは`pnpm media`で行う。

派生元: REQ-DIST-001

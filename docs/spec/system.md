# システム仕様

拡張機能、MCPサーバー、フォーム画面が外から見てどう振る舞うかを定めます。各項目はシステムテスト(`test/system`)で検証します。拡張機能の項目は、配布物をVS Codeの代役の上で動かして検証します。

## フォームの設計図

### SPEC-FORM-001 設計図の形

AIはフォームを次の形のJSONで指定する。

| キー          | 型             | 必須 | 制約        |
| ------------- | -------------- | ---- | ----------- |
| `title`       | 文字列         | ○    | 1〜80文字   |
| `description` | 文字列         |      | 300文字以下 |
| `fields`      | 項目の配列     | ○    | 1〜20個     |
| `computed`    | 計算結果の配列 |      | 8個以下     |
| `submitLabel` | 文字列         |      | 20文字以下  |

項目は`type`で種類を区別し、すべての項目が次を持つ。

| キー       | 型     | 必須 | 制約                                           |
| ---------- | ------ | ---- | ---------------------------------------------- |
| `id`       | 文字列 | ○    | 英字か`_`で始まり、英数字と`_`だけの40文字以下 |
| `label`    | 文字列 | ○    | 1〜60文字                                      |
| `reason`   | 文字列 |      | 推測の根拠。120文字以下                        |
| `advanced` | 真偽値 |      | 真なら「詳細」の中に畳む                       |

種類ごとのキーは次のとおり。

| `type`   | キー                                                                                                  |
| -------- | ----------------------------------------------------------------------------------------------------- |
| `text`   | `default`(500文字以下)、`placeholder`(80文字以下)、`multiline`                                        |
| `number` | `default`、`min`、`max`、`step`(正の数)、`prefix`と`suffix`(各8文字以下)                              |
| `choice` | `options`(2〜12個。各`value`と`label`は60文字以下、`description`は120文字以下)、`default`、`multiple` |
| `toggle` | `default`、`note`(40文字以下)                                                                         |

計算結果は`id`、`label`、`expression`(300文字以下)と、任意の`prefix`、`suffix`、`decimals`(0〜4)、`primary`を持つ。

- 項目と計算結果の`id`には、計算式の真偽値の予約語`true`と`false`を使えない。大文字と小文字は区別する。
- `__proto__`は有効な`id`として扱い、計算結果の表示と回答の`computed`にもその名前で保持する。

派生元: REQ-ASK-001, REQ-ASK-002, REQ-ASK-003

### SPEC-FORM-002 設計図の意味的な検査

次のいずれかに当たる設計図は受け付けず、問題をすべて列挙して返す。

- 項目と計算結果の`id`が重複している
- 数値項目で`min`が`max`以上、または`default`が範囲外
- 選択項目の`default`が選択肢にない、または`multiple`と`default`の形(単一か配列か)が合わない
- 複数選択の`default`に同じ値が複数ある。空の配列や重複のない配列は受け付け、選んだ数と計算で使う数を一致させる
- 計算式が文法に合わない、または未定義の`id`や自分より後の計算結果を参照している

派生元: REQ-ASK-001

### SPEC-EXPR-001 計算式

計算式は次を使える。評価できない場合(0での割り算など)の結果は「—」と表示する。

- 数値、`"`か`'`で囲んだ文字列、`true`、`false`
- 項目と、自分より前の計算結果の`id`。数値項目は数値、切り替え項目は真偽値、単一選択は選んだ`value`、複数選択は選んだ数、文字列項目は文字列になる
- `+` `-` `*` `/` `%`、比較`<` `<=` `>` `>=` `==` `!=`、論理`&&` `||` `!`、条件`条件 ? 値 : 値`、かっこ
- 関数`min` `max` `abs` `floor` `ceil` `round`(`round(値, 桁数)`も可)

- `1e999`など有限でない数値リテラルは評価できないものとし、回答の計算結果は`null`になる。その値を使う比較や後続の計算結果も評価できない。短絡評価や条件分岐で使われない値は結果に影響しない。

派生元: REQ-ASK-003

## MCPサーバー

### SPEC-MCP-001 質問のツール

MCPサーバーは、AIから呼べるツール`ask_form`を公開する。

- 入力は SPEC-FORM-001 の設計図
- 読み取り専用で外の世界に触れない注釈(`readOnlyHint: true`、`openWorldHint: false`)を持ち、実行前の確認も結果の確認も求めない
- `_meta.ui.resourceUri`で SPEC-MCP-002 の画面を指す

派生元: REQ-ASK-001, REQ-ANS-001

### SPEC-MCP-002 画面のリソース

MCPサーバーは`ui://ask-form/form.html`を、MIMEタイプ`text/html;profile=mcp-app`の1つのHTMLとして返す。

派生元: REQ-ASK-001

### SPEC-MCP-003 回答を待つ

`ask_form`は、画面から結果が届くまで結果を返さない。結果は次のいずれかで、`structuredContent`と、同じ内容のJSONを含む文章で返す。

| `status`         | 意味             | ほかのキー                                                        |
| ---------------- | ---------------- | ----------------------------------------------------------------- |
| `submitted`      | 回答した         | `values`、`changedByUser`(推測値から変えた項目の`id`)、`computed` |
| `delegated`      | AIに任せた       | `values`(推測値のまま)、`computed`                                |
| `answer_in_chat` | チャットで答える | なし                                                              |

`structuredContent`には、AIが次にすべきことを書いた文章を`next`として加える。`answer_in_chat`の`next`には、作業を区切って利用者の発言を待つよう指示する。

- 複数選択の差分は並び順を無視し、値ごとに比べる。値にNUL文字があっても、異なる選択は`changedByUser`に含める。

派生元: REQ-ANS-001, REQ-ANS-002, REQ-ANS-003

### SPEC-MCP-004 設計図の誤り

`ask_form`は SPEC-FORM-001 または SPEC-FORM-002 に反する設計図を受け取ると、待たずに誤りとして返し、AIが直せるよう問題の一覧を示す。

派生元: REQ-ASK-001

### SPEC-MCP-005 回答を受け取るツール

MCPサーバーは画面専用のツール`form_answer`を公開する。AIからは見えない(`_meta.ui.visibility`が`["app"]`)。

- 入力は、フォームの鍵、操作(`submit`、`delegate`、`chat`)、`values`
- 鍵に対応する待機中の`ask_form`に結果を渡す。同じ鍵の待機が複数あれば先に始まったものから順に渡す
- `values`を設計図に照らして検査し、合わなければ誤りを返す
- 複数選択の回答に同じ値が複数あれば拒否し、画面の選択数と計算結果が食い違う値を受け付けない
- 鍵に対応する待機がなければ、受け付けられないことを示す誤りを返す
- 回答を渡す処理が待機数の通知中に中断されても、台帳から外した質問には回答が届き、未完了の待機を残さない

派生元: REQ-ANS-001, REQ-CANCEL-001

### SPEC-MCP-006 フォームの鍵

フォームの鍵は、`ask_form`が受け取った引数をそのまま正規化したJSONから決まる。キーの順序が違うだけの引数からは同じ鍵が得られ、画面とサーバーで同じ鍵になる。

派生元: REQ-ANS-001

### SPEC-MCP-007 中断

`ask_form`の呼び出しが取り消されると、その待機は消え、以後その鍵への`form_answer`は SPEC-MCP-005 の誤りになる。

HTTPの応答を切断しなくても、同じMCPセッションから届く`notifications/cancelled`の`requestId`に対応する呼び出しを取り消す。他の呼び出しは待機を続ける。

画面専用の読み取り専用ツール`form_status`は、フォームの鍵を受け取り、`pending`(待機中)、`answered`(回答済み)、`cancelled`(中断)、`unknown`(記録なし)を返す。確認するだけでは回答や待機数を変えない。

派生元: REQ-CANCEL-001

### SPEC-MCP-008 送り直しのツール

MCPサーバーは画面専用のツール`form_resend`を公開する。設計図、ツールの結果としてCopilotへ渡した回答の値、新しい値を受け取り、差分がなければ誤りを返す。差分があれば、差分を述べた文章と、全項目の値を書いたJSONの添付を返す。添付はMCPのリソース`ask-form://answers/<uuid>/<slug>.json`として読め、送り直しごとに別のリソースになる。表示名は題名から整形した`<slug>.json`とし、UUIDを含めない。

- 自動送信のツールは公開せず、文章と添付を準備するだけとする。
- 添付は拡張機能の永続領域へ保存してから返す。同じ保存先を使う新しいサーバーでも同じURIから読み取れ、64件を超えて新しい添付を作っても消えない。保存失敗はツールの誤りとして返す。
- リソースの読込はUUIDとファイル名で保存先を参照する。存在しない添付と保存先の外を指すパスは拒否する。
- 添付名は40コードポイントまでとし、補助平面の文字を分断せずURIに符号化できる。

派生元: REQ-RES-002, REQ-RES-003

### SPEC-MCP-009 接続の保護

MCPサーバーは`127.0.0.1`の空いているポートでだけ待ち受け、起動ごとに作る秘密のトークンを`Authorization`ヘッダーに持たない要求と、`Origin`ヘッダーを持つ要求を拒否する。

派生元: REQ-SEC-001

## フォームの画面

### SPEC-UI-001 初期表示

画面は設計図の推測値で各項目を表示し、推測の根拠を項目の下に示す。利用者が推測値から変えた項目では、根拠の代わりに「あなたが変更」と示す。`advanced`の項目は閉じた「詳細」の中に表示する。

- 複数選択の値にNUL文字があっても異なる選択への変更を検出する。並び順だけの違いは変更と扱わない。

派生元: REQ-ASK-002

### SPEC-UI-002 計算結果

画面は値が変わるたびに計算結果を更新する。`primary`の計算結果は大きく表示する。

派生元: REQ-ASK-003

### SPEC-UI-003 回答の操作

画面は「AIに任せる」「チャットで答える」と、主ボタン(`submitLabel`、既定は「この内容で進める」)を持つ。フォーム内で⌘/Ctrl+Enterを押すと主ボタンと同じ操作になる。そのとき入力中の値は先に確定し、数値は範囲内に収める。

派生元: REQ-ANS-001, REQ-ANS-002, REQ-ANS-003, REQ-ANS-004

### SPEC-UI-004 回答後の要約

回答後、画面は全項目の値の要約に切り替わり、`changedByUser`の項目に印を付ける。ツールの結果を受け取ったときも同じ要約を表示する。`answer_in_chat`の後は値を示さない。

派生元: REQ-RES-001

### SPEC-UI-005 送り直し

要約の「変更して送り直す」で編集に戻る。ツールの結果としてCopilotへ渡した回答から変えた項目に「回答から変更」と印を付け、変えた項目の数を示す。回答と同じ値なら送信ボタンを押せない。ボタンを押すとSPEC-MCP-008を呼ぶ。

- デスクトップ版では、返った文章と`resource_link`添付をMCP Appsの`ui/message`でフォームのある会話の入力欄に置くだけとし、自動送信しない。要約に戻り「チャットの入力欄に入れました。内容を確かめて送信してください」と示す。英語では同じ内容を英語で示す。利用者がその会話の入力欄でEnterを押して送信する。
- 入力欄に置けなければ、その会話を開いて入力欄を空にするよう従来どおり示し、編集を続けられる。
- web版ではSPEC-EXT-003の下書きにして要約に戻り、同じ案内を示す。
- 下書きを置いても差分の基準は更新しない。下書きを送信しなかった場合も同じ変更を再び置ける。基準の回答に戻した場合だけ変更なしとする。
- 下書きの準備中は編集できない。要約は最後に下書きへ置いた編集値を示す。再編集のキャンセルではその値に戻し、差分の基準と混同しない。

- 複数選択の値にNUL文字があっても異なる選択なら送り直せる。並び順だけの違いでは送り直せない。

派生元: REQ-RES-002, REQ-RES-003

### SPEC-UI-006 中断と期限切れ

ツールの取り消しを受け取ったとき、または`form_answer`が受け付けられないと返したとき、画面はそれを示し、回答の操作をできなくする。

回答を待つ画面は`form_status`でも状態を確認し、ホストが`ui/notifications/tool-cancelled`を送らなくても、サーバーが中断を記録していれば中断を表示する。未登録や通信の誤りは中断と扱わない。回答後や中断後は確認を止め、遅れた返答で要約を閉じたり中断したフォームを再開したりしない。

- web版のパネルが読み込み中に取り消されても、初期化後に中断を表示する。状態の定期確認や回答の試行を待たない。

派生元: REQ-CANCEL-001

### SPEC-UI-007 テーマ

画面は、MCP Appsのホストから受け取る色と文字の変数を使い、変数がなければVS Codeの変数を使う。ハイコントラストのテーマでは、ボタンと切り替えに枠線を付ける。

派生元: REQ-LOOK-001

### SPEC-UI-008 アクセシビリティ

画面の操作要素はすべてラベルを持つ本物のフォーム部品で作り、フォーカスが見え、axeの検査で違反がない。

派生元: REQ-A11Y-001, REQ-ANS-004

### SPEC-UI-009 表示の言語

画面の文言は、ホストから受け取るロケールが日本語なら日本語、それ以外なら英語で表示する。

派生元: REQ-LOOK-001

### SPEC-UI-010 画面への通知の送り主

- 初期化、ツールの結果、中断、ホストの表示設定、呼び出しへの返答は接続先のホストからだけ受け付ける。別のウィンドウやフレームから届いたメッセージで画面や回答の受け付け状態を変えない。
- ホストのoriginが分かる場合は一致も検査する。直接読めない場合は、そのホストから最初に受け付けたJSON-RPCのoriginを保持し、以後異なるoriginを拒否する。

派生元: REQ-SEC-001, REQ-CANCEL-001

## 拡張機能

### SPEC-EXT-001 MCPサーバーの登録

デスクトップ版の拡張機能は、起動時に SPEC-MCP-009 のMCPサーバーを動かし、VS CodeにHTTPのMCPサーバーとして登録する。

- 待ち受けの開始に失敗した場合は起動の失敗として呼び出し元に返し、MCPサーバーを登録しない。非同期の失敗も未処理の例外にしない。

派生元: REQ-ASK-001, REQ-SEC-001

### SPEC-EXT-002 待機の表示

待機中の`ask_form`が1つ以上ある間、ステータスバーに「Copilotが回答を待っています」を表示する。

派生元: REQ-WAIT-001

### SPEC-EXT-003 web版の下書き

web版の拡張機能は、送り先の会話を指定する手段がないため自動では送信せず、差分の文章を今開いているチャットの入力欄に下書きとして入れ、全項目の値を書いたJSONファイルを添付する。利用者が送り先を確かめて送信する。

- 添付は投稿ごとに一意なディレクトリに保存し、表示名は題名から整形した`<slug>.json`とする。例えば「交流会の条件」は`交流会の条件.json`と表示し、UUIDは表示名に含めない。同じ題名やファイル名に整形すると同じになる題名で同時に送り直しても、以前の投稿に添付した値を上書きしない。

派生元: REQ-RES-002

### SPEC-EXT-004 web版

web版の拡張機能は、`ask_form`と同じ入力と結果を持つツールを拡張機能のツールとして登録し、呼ばれるとフォームをエディター横のパネルに表示して回答を待つ。このツールはweb版でだけ有効になる。

- 取り消し後もパネルのホストは中断状態を保持する。後から画面が初期化されたら、設計図に続いて中断を通知する。

- web版の受け入れテストは、拡張機能側の正常終了とブラウザ側の回答・要約の確認が両方成功してから終了する。片方でも失敗すれば失敗とする。

派生元: REQ-WEB-001, REQ-CANCEL-001

### SPEC-EXT-005 起動・サイズ・検査の予算

拡張機能はVS Codeの起動完了後に読み込まれる。バンドルの読み込みと起動処理は`budgets.json`の`activationMs`以内に終わり、各バンドルの大きさは`budgets.json`の`size`の上限を超えない。

- `timed.ts`による検査は`budgets.json`の時間を超えたら終了を要求し、1秒の猶予後に強制終了して失敗とする。受け入れテストを含む子と孫を同じプロセスグループで止め、直下の子だけが先に終了しても強制終了を取り消さない。Windowsではプロセスツリーを終了する。

派生元: REQ-PERF-001

## リリース

### SPEC-REL-001 配布前の検査と公開

- mainへのpushでpackage.jsonかCHANGELOG.mdが変わったとき、またはworkflow_dispatchで開始する。originに`v<version>`がなければ実行コミットにタグとリリースを作り、既存なら公開をスキップする。タグの照会失敗時は公開しない。同時に複数のリリースを実行せず、実行中のリリースを取り消さない。

- タグはpackage.jsonのversionに`v`を付けたものと一致し、版数は先頭の余分な0や接尾辞のない`major.minor.patch`とする。CHANGELOG.mdの`## <version>`の項には空でない箇条書きが1つ以上必要で、不備があれば公開を止める。
- minorが奇数ならプレリリース、偶数なら正式リリースとする。検査CLIは判定をGITHUB_OUTPUTがあれば追記し、なければ標準出力に出す。任意の第2引数で指定したファイルに対象版の本文だけを書き出す。
- リリースは検査とテスト後にVSIXを作り、その版の変更履歴を説明としてGitHub ReleasesへSHA256SUMS.txtとともに公開し、VSIXの出所を証明する。トークンがある配布先だけ追加公開し、各配布先へプレリリースの指定を渡す。
- CIのVSIX成果物は単一ファイルをZIPに包まず保存し、test-resultsはZIPを維持する。

派生元: REQ-DIST-001

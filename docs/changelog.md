# 変更履歴の書き方

CHANGELOG.mdは、この拡張機能の利用者が、更新で何が変わるかを知るために読みます。各版の項は、そのままGitHub Releases、Visual Studio Marketplace、Open VSXのリリースノートになります。書き方は[Keep a Changelog](https://keepachangelog.com/)に合わせます。

## いつ書くか

利用者に見える変更を入れるPRで、`## 未リリース`に項目を足します。mainにマージされてCIが成功すると、`## 未リリース`の項目を公開するリリースPRが作られ、自動でマージされてプレリリースとして公開されます。書き忘れると公開されません。

利用者に見える変更とは、次のどれかです。

- フォームの見た目、操作、文言が変わる。
- CopilotやMCPのクライアントから見たツール、設計図、結果の形が変わる。
- VS Codeの設定、コマンド、動く環境が変わる。
- 不具合が直る。

次の変更は書きません。

- 依存の更新。ただし、利用者に見える不具合や脆弱性が直る場合は書きます。
- テスト、CI、ビルド、文書だけの変更。
- 振る舞いの変わらないリファクタリング。

`src/`を変えたのに利用者に見える変更が無いPRには、`no-changelog`ラベルを付けます。ラベルの無いPRで`src/`が変わり、`## 未リリース`の項目が増えも変わりもしなければ、CIのChangelogが失敗します。

## 種別

項目は、次の種別の見出しの下に書きます。見出しはこの順に並べ、項目の無い種別の見出しは置きません。

| 見出し             | 書く変更                             |
| ------------------ | ------------------------------------ |
| `### 追加`         | 新しい機能、設定、項目               |
| `### 変更`         | 既にある機能の振る舞いや見た目の変更 |
| `### 非推奨`       | 今後なくす予定の機能                 |
| `### 削除`         | なくした機能                         |
| `### 修正`         | 不具合の修正                         |
| `### セキュリティ` | 脆弱性の修正                         |

`pnpm lint`は、`## 未リリース`の項目が種別の見出しの下にあるかと、見出しが上の6つのどれかかを確かめます。

## 1項目の書き方

- 1項目に1つの変更を書きます。1つのPRで複数の変更を入れたら、項目を分けます。
- 利用者から見た変化を書きます。変更したファイル、関数、内部の仕組みは書きません。
- 文末は「〜しました」「〜できます」の敬体にそろえます。
- 振る舞いを変えた時は、「これまでは〜」で前の振る舞いを添えます。
- 利用者が何かをする必要がある時は、何をすればよいかを書きます。
- 設定名、ツール名、結果の項目名は`chat.autoReply`のようにコードの書式で書きます。
- PRの番号やcommitのハッシュは書きません。

例を示します。

```markdown
## 未リリース

### 変更

- VS Codeの設定`chat.autoReply`が有効な間は、フォームを出して待たないようにしました。これまでは、利用者が席を外していても回答を待ち続けていました。
```

## 版の項

`## 未リリース`の見出しは、リリースのワークフローが`## <version>`に書き換えます。手で版の見出しを作るのは、正式リリースを出す時だけです。手順は[リリースの基準](release.md)にあります。
